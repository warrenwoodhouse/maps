# Accessibility
Accessibility matters to my projects across my entire web development journey.
If you feel like you can help, contribute or support my projects in any way, please check out the [Maps Forum](https://github.com/warrenwoodhouse/forums/labels/maps).
This document covers the accessibility commitments, contributor
expectations and issue-reporting process.

If you or a friend have any technical experiences in mapping using the Leaflet framework, feel free to contribute and leave your code either in a new discussion thread or on the forum (link provided).

## Priorities
I hope to make my maps as accessible as possible. Though this is a challenging goal,
it’s an aspirational goal to aim towards.

My maps currently support keywords, screen readers and language supports as well as various browsers and television models.

## Contributor expectations
This section applies to contributions, including relevant testing, documentation and continuous integration
checks. Name specific tools only when the project uses them and explain
what evidence contributors should include with user-facing changes.

## Reporting accessibility issues
I have provided a direct, accessible way to report a barrier or request help.
You can add useful context such as the affected task, URL, observed behaviour,
browser, operating system and assistive technology. Make screenshots or
recordings optional and do not require disability disclosure.

### Severity
If your project uses severity levels, define them and give practical
examples based on how strongly a barrier affects a user's ability to
complete a task. Keep labels consistent with your issue template and
resolution targets if those processes exist. Maintainers can assign or
confirm severity during triage; reporters do not need to.

### How we respond
I will respond within a timely fashion of 1 week or within the hour depending on my availability.
